# Обнаружение fin_scan используя Suricata.

## Теория:

### FIN-сканирование

FIN scan — метод сканирования портов, который использует **Nmap** для определения их состояния. FIN scan метод, при котором **Nmap** отправляет TCP пакет с флагом FIN и анализирует ответ целевого хоста. В зависимости от состояния порта возможны следующие варианты:

#### Открытый порт

При стандартном поведении целевой хост не отвечает на пакет с флагом FIN. Поэтому **Nmap** не может определить открыт порт или трафик фильтруется. 

#### Закрытый порт

Целевой хост отвечает пакетом `RST`, указывая, что порт закрыт.

#### Фильтруемый порт

Если ответ отсутствует **Nmap** может определить порт как open|filtered.

## Стенд

**Атакующий:** Kali Linux, 192.168.10.10  
**Цель:** Ubuntu Server (Suricata IDS), 192.168.10.2

## Механизм детекта: fin_scan (Nmap -sF)

Обнаружение FIN сканирования портов.

## Воспроизведение атаки

Команда запуска сканирования с машины атакующего:

```
sudo nmap -sF 192.168.10.2
```

_Логика_: сканирование с флагом -sF без дополнительных ключей - это сканирование 1000 самых популярных портов. Список портов хранится в файле **/usr/share/nmap/nmap-services** который используется Nmap.

## Сигнатура Suricata

```
alert tcp any any -> $HOME_NET any (msg:"FIN_SCAN_DETECTED"; flags:F; threshold: type both, track by_src, count 10, seconds 5; sid:1000003; rev:1;)
```

_Логика:_ Первые 9 пакетов учитывается при подсчете в памяти и не пишет в eve.json но в логах ничего нет. На 10-м пакете порог пройден, будет выдан алерт, при этом в режиме type_both будет зафиксирован 1 алерт, даже если уже было просканировано 150 портов за один раз.

## Проверка правила

```
sudo suricata -T -c /etc/suricata/suricata.yaml -v
```
