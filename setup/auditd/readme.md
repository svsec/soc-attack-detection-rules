# Подсистема аудита Linux (auditd)

**`auditd`** — фоновая служба подсистемы аудита, предназначенная для сбора системных вызовов и событий, происходящих на сервере и рабочих станциях, на основе правил, прописываемых администратором.

---
## Типы правил в auditd

Существует два типа правил:
### 1. Правила наблюдения за файлами и директориями
#### Синтаксис:
```
-w -p "permission" -k 
```
#### Разбор параметров:
* **`-w`** — указывает путь к файлу или папке.
* **`-p`** — определяет, какие действия отслеживать. Параметр комбинируется из следующих флагов:
  * **`r`** — чтение (*read*)
  * **`w`** — запись/изменение (*write*)
  * **`x`** — выполнение (*execute*)
  * **`a`** — изменение атрибутов/владельца (*attribute*)
* **`-k`** — текстовая метка (ключ), по которой можно быстро найти событие в общем логе.

> **Пример:**
> -w /etc/passwd -p wa -k identity_changes
> *Смысл правила: следить за записью и изменением атрибутов файла `/etc/passwd`, а каждому такому событию присваивать уникальную метку `identity_changes`.*

### 2. Правила для системных вызовов. 
### Системный вызов - это вызов (запрос на действие) который происходит из пользовательского пространства в ядро ОС
#### Синтаксис:
```
-a always,exit -F arch=b64 -S -k 
```
#### Разбор параметров:
* **`-a`** — добавить новое правило для системного вызова
* **`always,exit`** — пара параметров, где: 
    * `always` — действие (записывать событие всегда, когда условия совпадают). 
    * `exit` — список фильтрации ядра (делать запись на выходе из системного вызова, чтобы зафиксировать его результат).
* **`-F`** — фильтр любых параметров(популярные):
    1) -F arch=b64 (по разрядности)
    2) -F auid=1000 (по id пользователя)
    3) -F success=0 (по неуспешному выполнению)
* **`-S`**— имя или номер системного вызова (`kill`, `chmod`, `execve`)
* **`-k`** — текстовая метка (ключ), по которой можно быстро найти событие в общем логе.
 **Пример:**
> -a always,exit -F arch=b64 -S execve -k exe_file
> *Смысл правила: логировать запуск любых исполняемых файлов и команд (через системный вызов `execve`) в 64-битной системе и присваивать этим событиям уникальную метку `exe_file`.*

## Применение правил и поиск логов

* **`/var/log/audit/audit.log`** — главный лог-файл, куда записываются все события безопасности.
* **`sudo augenrules --load`** — команда для применения новых правил из конфигурационных файлов.
* **`sudo ausearch -k key_name`** — утилита для быстрого поиска событий в логе по текстовой метке (ключу).

> **Важно:** Если в конце файла правил прописать параметр **`-e 2`**, конфигурация аудита намертво блокируется. После этого никто (даже `root`) не сможет изменить правила или выключить сбор логов до полной перезагрузки сервера.
