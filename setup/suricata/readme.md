**`IDS/IPS Suricata`** — система обнаружения (Intrusion detection system) и предотвращения (Intrusion prevention system) вторжений, мониторинга сетевого трафика. Для работы использует правила (сигнатуры), которые позволяют выявлять подозрительную активность.

### Система работает в двух режимах

 1. IDS (Intrusion detection system) — пассивный режим, анализирует трафик на соответствие заданным правилам без вмешательства. Обычно подключается через SPAN порт на сетевом оборудовании.
2. IPS (Intrusion prevention system) — активный режим (inline), трафик проходит непосредственно через систему, что позволяет блокировать подозрительную активность в соответствии с правилами.
#### Синтаксис:
```
[Action] [Protocol] [src_ip] [src_port] [dir] [dst_ip] [dst_port] ([msg]; [content]; [sid]; [rev];)
```
#### Разбор параметров:
* **`Action (действие)`**  — что делать если трафик совпал с правилом.
	alert —  сгенерировать предупреждение и записать в лог
	drop — заблокировать пакет(только в режиме inline)
	pass — пропустить пакет
	reject — заблокировать и отправить отчет об ошибке отправителю
* **`Protocol`** — на каком уровне есть 
    сетевой/транспортный  — ip, icmp, tcp, udp
    прикладной  — https, ftp, dns, smb ssh и другие
* **`src IP and Ports`**
    ip - можем писать конкретный (192.168.x.x), подсеть (192.168.1.0/24), переменные ($HOME_NET, $EXTERNAL_NET) или списки через запятую в ( ). Отрицание (!): $HOME_NET любой ip кроме внутренней сети   
    порты: конкретный порт (80), диапазон (1024:65535), список портов ([ 80,443 ]) 
* **`dir (direction)`**  — в какую сторону должен лететь пакет, чтобы правило сработало.
    -> от источника слева к назначению справа
    <> двунаправленное движение в обе стороны
    ПРИМЕЧАНИЕ: <- стрелки влево не существует
* **`msg`** — сообщение, которое будет отображаться при срабатывании правила. Позволяет понять, что именно обнаружила сигнатура.
* **`content`** — задаёт содержимое, которое Suricata должна найти в анализируемом трафике для срабатывания правила.
* **`sid`** — уникальный идентификатор правила. Используется для однозначного определения конкретной сигнатуры. Для пользовательских правил обычно используются значения от `1000000` и выше.
* **`rev`**  — номер версии правила. Увеличивается при изменении или обновлении существующей сигнатуры.
### Пример: 
```
alert icmp any any -> $HOME_NET any ( msg:"TEST ICMP"; sid:1000001; rev:1; )
```
*Смысл правила: сгенерируй алерт при обнаружении любого ICMP пакета направленного в нашу внутреннюю сеть"*
## Проверка и логи 

**Проверка конфигурации перед запуском:** sudo suricata -T -c /etc/suricata/suricata.yaml -v

**Основной лог файл:** /var/log/suricata/eve.json — все события в формате JSON.
